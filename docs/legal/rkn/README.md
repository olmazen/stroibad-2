# Пакет подготовки сайта EGOE к требованиям Роскомнадзора

Статус на 23.08.2026: `public-documents-ready-with-collection-off / blockers-open`. Публичные тексты подготовлены для публикации вместе с закрытым server gate: страницы сайта, технические журналы хостинга, локальное хранилище и Яндекс Карты продолжают работать, а онлайн-формы не принимают и не записывают персональные данные. Описанный в документах режим заявок начнёт применяться только после юридического утверждения, документированного решения об актуализации записи Роскомнадзора и отдельного server approval.

В реестре Роскомнадзора найдена запись Оператора № `64-22-007585`. Наличие записи не снимает необходимость проверить, охватывает ли она новую веб-форму, e-mail, технические поля и SQLite на REG.RU. Результат и границы проверки зафиксированы в [`operator-registry-check.md`](./operator-registry-check.md). Никакое уведомление или изменение сведений из репозитория не направлялось.

## Принцип публикации

Публичные документы должны описывать фактическую работу сайта. В текущем режиме браузер может загружать страницы и Яндекс Карты, использовать заявленное локальное хранилище и создавать стандартные запросы в access log хостинга, но online collection gate закрыт: PHP-обработчик не создаёт новых записей заявок или доказательств согласия. Целевая схема после отдельного допуска: браузер → PHP-обработчик на REG.RU → первичная и единственная запись полной заявки в SQLite вне web-root в РФ. Весь маршрут Google Apps Script/Telegram выключен: outbox не отправляет ни фиксированные сигналы, ни технические значения, ни поля заявки.

Dormant `signal` в коде содержит только два постоянных текстовых поля. Однако один вызов сразу после каждой записи создаёт у Google/Telegram транспортное время, которое может сопоставляться с `created_at` в SQLite. Поэтому одного постоянного тела недостаточно для вывода об отсутствии персональных данных: такой event-сигнал рассматривается как потенциальная трансграничная передача и остаётся выключенным до выполнения процедуры по ст. 12 152-ФЗ. Dormant `technical` (`_subject`, `leadId`, `formId`, `page.path`, `createdAt`) и `full` (technical плюс `fields`) также выключены; полный режим дополнительно потребует новой цели, основания, публичных документов и approval владельца. FormSubmit не используется. Яндекс Карты загружаются автоматически с `loading="lazy"`; WhatsApp открывается только по клику, MAX пока неактивен. Яндекс Метрика, Envybox и Unisender не используются.

Российская первичная запись закрывает только требование локализации. Она не отменяет процедуру трансграничной передачи, если в последующий маршрут Google LLC / Telegram Messenger Inc. попадут персональные данные либо сохраняемая связь с заявкой. Весь relay остаётся выключенным до получения сведений и оценки по ч. 5 ст. 12 152-ФЗ, отдельного уведомления Роскомнадзора, определения стран/получателей и регламента удаления. Для полного режима дополнительно нужны отдельная цель и основание, обновление Политики/согласия и новый approval владельца. Данные аккаунтов и транспортные метаданные сервисов оцениваются отдельно в общей карте обработки Оператора.

Уведомление Роскомнадзора нельзя заполнять только по сайту, если организация также обрабатывает данные работников, кандидатов, контрагентов, представителей заказчиков или иных лиц. Подготовленный файл содержит готовый сайт-специфичный блок; его нужно объединить с общей картой процессов ООО.

Публичная `/privacy/` также описывает только обработку, связанную с Сайтом. Она не заменяет общую политику и локальные акты Оператора по всем кадровым, договорным, бухгалтерским и иным фактическим процессам.

## Порядок утверждения

1. Подтвердить ответственного за ПД, реальные даты начала процессов, сроки хранения/удаления и полный перечень процессов ООО.
2. Проверить работающий PHP/SQLite endpoint: российское место базы, права доступа, журнал согласий, резервирование, удаление, инциденты и секреты вне Git.
3. Сверить договорное лицо REG.RU для хостинга и корпоративной почты, место каждой базы и условия поручения. Публичные правила REG.RU не заменяют договор Оператора.
4. До завершения процедуры ст. 12 держать весь Google Apps Script/Telegram relay выключенным. Если канал понадобится, повторно утвердить точные реализованные payload, протестировать отсутствие неожиданных значений, учесть корреляцию по transport timestamp и установить TTL. Полный режим считать отдельным релизом с новыми документами и approval.
5. Сопоставить запись Роскомнадзора № `64-22-007585` с полной фактической архитектурой сайта и общей картой процессов ООО; письменно решить, требуется ли уведомление об изменении сведений, и сохранить доказательства результата.
6. Проверить отдельные основания на публикацию имени/должности/изображений представителей Оператора по ст. 10.1 152-ФЗ.
7. Провести юридическое утверждение публичной версии `2026-08-23` и UX форм в собранном сайте.
8. Публичные документы допускается публиковать только вместе с закрытым collection gate. Работающие формы включать лишь после закрытия блокеров, юридического утверждения и отдельного server approval. Уведомления государству в рамках этого репозитория не отправляются.
