# Снимки редакций согласия

Backend сохраняет в `consent_evidence` версию согласия и URL документа. Чтобы изменяемый URL `/consent/` можно было сопоставить с точным текстом, для каждой принимаемой переходной версии фиксируются SHA-256 и Git blob неизменного HTML.

| Версия | Редакция | SHA-256 `consent/index.html` | Git blob | Источник |
|---|---|---|---|---|
| `2026-08-23` | 23.08.2026 | `a725d1cae8657d1dd8d9c4aa4e73291d749337b4ad63cca52ed04dd5a981a240` | `fe20ea91234cf1ebc5f3c01bde231914babec605` | production release `4a5d627cb75ca290892650c9bb19cc45118a03e5` |
| `2026-08-27` | 27.08.2026 | `33dee6cc877788aa610e794de2ce1aa52ece873bf099a036dbcc3e6951556bac` | `4b1cc7ac0f097c22798c9bc2df4d9cb3bb79ba6d` | production release `05779e39a27ff27b37eaa67ff2f28eae2dff7fe2`; cached-client compatibility |
| `2026-09-04` | 04.09.2026 | `7ca07ec97832543ffb542c81f323c4d776230432cdb7f5cc78e4edd8c74431a2` | `aa10407233b177d6daa9252bb7d5a44f42596649` | целевой файл pre-release ветки; итоговый release SHA фиксируется после публикации |

Проверка перед публикацией:

```sh
shasum -a 256 consent/index.html
git hash-object consent/index.html
```

При любом изменении юридического текста создаётся новая версия согласия и новая строка. Существующую строку и соответствующий Git blob не заменяют. Матрица перехода зафиксирована явно: `2026-09-04` — российская SQLite, прямой Telegram и корпоративная email-копия REG.RU; `2026-08-27` — российская SQLite и прямой Telegram без email для ранее открытых/кэшированных страниц; `2026-08-23` — только локальная российская запись без journey и любого внешнего задания. Любая иная версия отклоняется. Публичную `2026-09-04` нельзя выпускать отдельно от поддерживающих её frontend/backend; rollback выполняется полным согласованным release, а не заменой одной страницы.
