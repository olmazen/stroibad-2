# EGOE — публичный сайт

Статический сайт производителя малых архитектурных форм и металлоизделий. В репозитории пока находится legacy-набор готовых HTML-страниц; поверх него добавлен безопасный слой сборки, проверок и релизов.

Главное правило: **публикуется только содержимое `dist/`, никогда не корень репозитория**.

## Быстрый старт

Требуется Node.js 20 или новее.

```bash
npm ci
npm run check
npm run build
```

- `npm run build` формирует чистый публичный артефакт в `dist/` по явному allowlist.
- `npm run check` собирает сайт и проверяет состав артефакта, локальные ссылки, хеши и базовые контракты.
- `npm run verify` выполняет полный локальный релизный контур.

`dist/` генерируется заново и не должен редактироваться или коммититься.

## Структура

```text
├── index.html, maf/, ...       legacy-источник публичных страниц
├── assets/                     runtime CSS, JS, изображения, модели и каталоги
├── tools/                      сборка, проверки и legacy-инструменты
│   └── dogovor/                временно публичный legacy-маршрут
├── config/site-contract.json   проверяемые границы и известный baseline
├── docs/                       архитектура, процесс, релизы, legal/RKN
├── .github/workflows/          CI, Pages staging и подготовка релиза
└── dist/                       генерируемый публичный артефакт
```

Репозиторий содержит только статический frontend. Корзина и КП работают в браузере, поиск читает JSON, 3D использует локальные модели и внешние библиотеки, формы передают обращения во внешние сервисы. Это важно: «ошибка backend» здесь обычно является ошибкой общего JavaScript, внешнего сервиса или рассинхронизации размноженных HTML/JSON.

## Как вносить изменения

1. Создать отдельный worktree/ветку от `origin/main`.
2. Изменить только область одной задачи.
3. Выполнить `npm run check` и проверить diff.
4. Отправить PR; CI приложит собранный `dist` как артефакт.
5. После проверки изменения могут попасть на GitHub Pages staging.
6. Production-публикация выполняется отдельно и только после явного подтверждения.

## Текущее ограничение

Это первый защитный слой, а не окончательный шаблонизатор. Общие меню и товарные данные всё ещё размножены в legacy-файлах. Их консолидация — отдельный этап, потому что одновременная перестройка сотен страниц и релизного контура сделала бы проверку результата ненадёжной.
