# EGOE — публичный сайт

Сайт производителя малых архитектурных форм и металлоизделий: legacy-набор готовых HTML-страниц, воспроизводимая публичная сборка и небольшой same-origin PHP-обработчик заявок. Поверх исходных страниц добавлен безопасный слой проверок и неизменяемых релизов.

Главное правило: **публикуется только содержимое `dist/`, никогда не корень репозитория**.

## Быстрый старт

Требуется Node.js 20 или новее.

```bash
npm ci
npm run check
npm run build
```

- `npm run sync:shell` обновляет сгенерированные header/navigation/footer на 305 стандартных страницах из одного источника.
- `npm run sync:data` обновляет поиск, каталог КП и закрытый реестр цен из `src/data/products.json`.
- `npm run sync:runtime-assets` подключает отдельный модуль заявок и ставит content-hash версии общего CSS/JS на 305 страницах, а также отдельного `kp.js` на `/kp/`, чтобы браузер не держал старый runtime месяц.
- `npm run check:shell` проверяет renderer, идемпотентность общей оболочки и структуру всех стандартных страниц.
- `npm run check:data` проверяет схему товаров, уникальность SKU/URL, страницы, цены и все ссылки на товарные ассеты.
- `npm run check:runtime` проверяет изоляцию 17 JS-функций, ограниченный журнал ошибок, content-hash ассетов, 3D-timeout и fallback на всех 75 Art Déco страницах и главной.
- `npm run check:leads` проверяет 287 форм, подтверждённый success, ошибки/timeout, защиту от двойного клика и состав multipart-запроса на поддельном транспорте, без реальных сетевых отправок.
- `npm run check:syntax` проверяет синтаксис всех JS/MJS до сборки.
- `npm run build` сначала отклоняет несинхронизированный общий каркас, затем формирует чистый публичный артефакт в `dist/` по явному allowlist.
- `npm run check` собирает сайт и проверяет состав артефакта, локальные ссылки, хеши и базовые контракты.
- `npm run verify` выполняет полный локальный релизный контур.

`dist/` генерируется заново и не должен редактироваться или коммититься.

## Структура

```text
├── index.html, maf/, ...       legacy-источник публичных страниц
├── src/shared/site-shell.json  единый источник шапки, меню и подвала
├── src/data/products.json      единый источник 276 товаров и цен
├── assets/                     runtime CSS, JS, изображения, модели и производные каталоги
├── api/leads/                  PHP endpoint и CLI для заявок; без конфигурации и базы
├── tools/                      сборка, проверки и legacy-инструменты
│   └── dogovor/                временно публичный legacy-маршрут
├── ops/                        инструкции и оболочки эксплуатации, не публикуются
├── config/site-contract.json   проверяемые границы и известный baseline
├── docs/                       архитектура, процесс, релизы, legal/RKN
├── .github/workflows/          CI, Pages staging и подготовка релиза
└── dist/                       генерируемый публичный артефакт
```

Корзина и КП работают в браузере, поиск читает JSON, а 3D использует локальные модели и локально размещённые библиотеки. Независимые блоки `site.js` запускаются через `EGOE_RUNTIME`: исключение одного блока записывается в ограниченный журнал и не останавливает остальные инициализаторы.

Формы вынесены в `assets/js/leads.js` и отправляют данные только в same-origin `/api/leads/`. Production-сбор включён отдельными серверными настройкой и маркером, а интерфейс показывает успех только после устойчивой записи заявки и доказательства согласия в SQLite на российском хостинге. Контакты в браузере не сохраняются. Для заявки браузер может приложить не более 20 посещённых в текущей вкладке за текущий день страниц без query/hash; этот маршрут живёт в `sessionStorage`, передаётся только вместе с подтверждённой заявкой и удаляется при закрытии вкладки.

Конфигурация, секреты, база, резервные копии и очередь находятся вне Git и публичного web-root. Full relay Google Apps Script → закрытая Telegram-группа реализован после российской записи, но по умолчанию выключен и требует отдельного защищённого `relay-approved`, точного SHA-256 разрешённого HTTPS URL и ответа `{"ok":true}`. При временной ошибке локальный outbox повторяет отправку; браузер никогда не обращается к Google или Telegram сам. Вложения остаются выключены.

Серверная CLI умеет ограниченно сопоставлять сохранённые заявки по нормализованным телефону/e-mail без новой таблицы и без сохранения производных идентификаторов. Отдельный ежедневный отчёт считает только агрегаты заявок и суммы запрошенных КП, а опционально читает Яндекс Вебмастер. Яндекс Метрика и иное браузерное аналитическое слежение для этого не используются.

## Как вносить изменения

1. Создать отдельный worktree/ветку от `origin/main`.
2. Изменить только область одной задачи.
3. Выполнить `npm run check` и проверить diff.
4. Отправить PR; CI приложит собранный `dist` как артефакт.
5. После проверки изменения могут попасть на GitHub Pages staging.
6. Production-публикация выполняется отдельно и только после явного подтверждения.

## Текущая модель данных

Общий каркас больше не поддерживается вручную в сотнях копий: HTML-регионы с маркерами генерируются из `src/shared/site-shell.json`, а CI запрещает рассинхронизацию. Товары и цены редактируются только в `src/data/products.json`; `assets/catalog.json`, `assets/products.json` и `assets/data/prices.json` являются производными и вручную не меняются.

В источнике 276 товарных карточек. Поиск дополнительно содержит 16 явно описанных страниц разделов, поэтому корректный размер поискового индекса — 292, а не 276. Контракт проверяет каждую сущность в её собственном grain, а не маскирует разные сущности одним счётчиком.
